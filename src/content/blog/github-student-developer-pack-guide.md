先打开 [GitHub Education benefits 设置](https://github.com/settings/education/benefits)确认状态。申请获批、Student Developer Pack 中的第三方权益、Copilot Student 激活是三个不同环节：Education 已通过但 Copilot 仍显示 Free 时，不要误买付费计划，先从 benefits 页面单独完成激活。

本文根据 GitHub 官方文档于 2026 年 9 月 1 日重新核对。合作方、期限和领取条件会变化，本文不保存一份容易过期的“全部权益清单”。

## 先按当前状态处理

| 看到的状态 | 下一步 | 完成标志 |
| --- | --- | --- |
| 尚未申请 | 准备当前在读证明并从 benefits 页面提交 | 页面显示申请已提交 |
| 申请被拒 | 按拒绝原因修正材料，不要重复创建账号 | 新材料能清楚证明当前学期在读 |
| Education 已通过，Pack 权益未出现 | 确认登录的是获批账号，再进入 [Student Developer Pack](https://education.github.com/pack)逐项领取 | 目标合作方显示领取入口或明确资格限制 |
| Copilot 仍显示 Free、试用或付费页 | 从 benefits 页面激活 Copilot Student，并等待权益同步 | Copilot 设置页显示学生计划可用 |
| Education 已过期 | 仍符合资格时重新申请 | benefits 页面重新显示有效学生身份 |

## 申请资格和材料

[GitHub 官方学生申请说明](https://docs.github.com/en/education/about-github-education/github-education-for-students/apply-to-github-education-as-a-student)要求申请者：

- 正在可授予学位或文凭的课程中就读；
- 能提供当前学生身份的证明；
- 使用 GitHub 个人账号；
- 年满 13 岁。

可接受材料的示例包括带当前注册日期的学生证、课程表、成绩单，以及学校出具的在读或关系证明。材料应同时让审核者看清姓名、学校和当前有效日期；不要上传与申请无关的身份证件信息，也不要把真实材料发给所谓“代认证”服务。

学校邮箱不是自动通过凭证。GitHub 会根据学校情况决定是否要求学术邮箱：

- 页面明确要求学术邮箱时，先把它添加到当前 GitHub 账号并完成验证；
- 学校不发学术邮箱时，提供学校官网说明或带学校抬头的正式证明；
- 学校域名未被识别时，联系 GitHub Education Support，并提供学校全名、官网和邮箱域名；
- 邮箱统一使用小写，不要使用 `name+school@example.com` 这类 plus addressing。

## 提交申请

1. 登录准备长期保留的 GitHub 个人账号，打开 [Education benefits](https://github.com/settings/education/benefits)。
2. 在 GitHub Education 区域选择 **Start an application**。
3. 填写学校与学生信息，按当前页面要求验证邮箱或上传材料。
4. 提交后回到同一页面查看状态，不要为了重试创建第二个个人账号。

预期结果是申请状态能在 benefits 页面查到。若材料上传完成但页面没有提交记录，先检查登录账号和网络状态，再重新进入申请入口；不要连续提交多份内容不同的材料。

## 申请被拒时怎么修正

[GitHub Education 访问排查文档](https://docs.github.com/en/education/about-github-education/github-education-for-students/solving-problems-with-your-github-education-access)列出的常见原因可以这样处理：

| 原因 | 最小修正 | 不要这样做 |
| --- | --- | --- |
| 图片模糊、日期不清或无法证明当前在读 | 重新拍摄完整文件，确保至少一个当前有效日期可读 | 裁掉学校、姓名或日期 |
| 学校邮箱域名未验证或发放规则过宽 | 补交学生证、成绩单或在读证明 | 只重复提交同一个邮箱 |
| 页面要求学术邮箱 | 联系学校取得邮箱；学校不提供时提交正式政策证明 | 购买或借用学校邮箱 |
| 邮箱已被另一个 GitHub 账号使用 | 保留获批账号并按官方流程合并个人账号 | 用多个个人账号重复领取 |
| 课程不授予学位或文凭 | 确认学校是否加入 GitHub Campus Program，或接受当前不符合 Pack 资格 | 伪造课程、学校或材料 |

GitHub 不支持把 Education 优惠直接转移到另一个账号。若确实有多个个人账号，应按官方账号合并流程处理，并保留已经获得权益的账号。

## 获批后领取 Student Developer Pack

Education 获批后，进入 GitHub Education portal 或 Pack 页面，按实际需要领取合作方权益。看到领取按钮并不表示合作方账号已经自动开通；部分服务还会要求：

- 创建或绑定合作方账号；
- 同意合作方自己的条款；
- 添加付款方式或在额度耗尽后转为付费；
- 满足额外年龄、地区或既有账号限制。

领取前记录开始日期、结束日期、自动续费规则和取消入口。官方说明指出，多数有时限的合作方优惠从真正设置或兑换时开始计时，所以暂时不用的服务不必提前激活。

## Copilot Student 仍显示 Free 怎么办

GitHub 官方明确说明：Education 审核通过和 Copilot Student 激活是两个步骤，权益同步可能需要几天。[Copilot Student 激活说明](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/enable-copilot/set-up-for-students)给出的路径是：

1. 打开 [Education benefits](https://github.com/settings/education/benefits)。
2. 在学生和教师的免费开发资源区域选择 **Learn more**。
3. 按提示激活 Copilot Student，并确认自己的 Copilot 使用策略。

如果账号仍显示 Copilot Free、试用或付费结账页：

1. 先确认 Education 状态为已验证，并且浏览器登录的是同一账号；
2. 打开 [Copilot 设置](https://github.com/settings/copilot)重新检查资格提示；
3. 也可以访问 GitHub 官方的 [Copilot 激活入口](https://github.com/github-copilot/free_signup)；
4. 如果只出现付费选项，不要完成购买；等待几天后重试；
5. 几天后仍未同步，再联系 GitHub Support，并附上状态页面、尝试时间和看到的错误文字，不要发送密码或恢复码。

完成标志是设置页显示学生计划已经启用，而不是只看到 Education 申请获批。GitHub 当前还会每月重新评估 Copilot Student 的资格，因此曾经激活不代表以后永久保留。

## 两年后续期和重新验证

[Student Developer Pack 条款](https://docs.github.com/en/education/about-github-education/github-education-for-students/github-terms-and-conditions-for-the-student-developer-pack)写明，学生验证有效期为两年，之后需要重新验证学生身份。Education access 到期后，如果仍符合资格，可以在 benefits 页面重新申请：

1. 确认当前仍在可授予学位或文凭的课程中就读；
2. 准备包含当前学期信息的新材料；
3. 在 GitHub Education 区域重新选择 **Start an application**；
4. 获批后分别检查 Pack、Copilot 和已领取的合作方账号。

重新通过 GitHub Education 不会重置所有第三方优惠。部分合作方不允许续领，限时优惠通常不能重复兑换，过去使用过的免费试用也可能与 Pack 优惠冲突。

## 第三方权益会变化

Pack 只是合作权益入口，第三方产品的合同关系、资格限制和数据处理由对应合作方负责。官方条款允许合作方调整、暂停或移除优惠，也不保证变更后仍能按旧条件领取。

决定使用某项权益前，同时检查：

- [Student Developer Pack 当前页面](https://education.github.com/pack)上的领取条件；
- GitHub Education 维护的 [合作方变更记录](https://github.com/github-education-resources/Student-Developer-Pack-Current-Partners-FAQ/blob/main/SDP-changelog.md)；
- 合作方自己的价格、续期、自动扣费、数据导出和删除规则。

不要为了“把权益用满”创建空项目或提前绑定支付方式。真正需要第三方服务时再领取，并在日历中记录到期前的导出与取消时间。

## 毕业或不再符合资格前

- 把 GitHub 恢复邮箱改为长期可用的个人邮箱；
- 确认重要仓库属于你能长期访问的个人账号或组织；
- 从第三方服务导出代码、数据库和项目文档；
- 检查免费额度结束后是否会自动扣费；
- 为必须继续使用的工具选择免费版、个人付费版或可迁移替代方案。

账号、项目与文件迁移可以继续看[大学生学习资料备份与毕业迁移](/blog/student-file-backup-guide/)。通过认证后，需要整理公开项目时看[GitHub 学生作品集指南](/blog/github-portfolio-for-students/)；想先比较其他正式学生计划，可查看[官方教育权益清单](/blog/edu-email-pro-benefits/)。
