# 2026 年 9–11 月内容增长路线图

## 目标与证据边界

本站集中在更接近真实搜索需求的学生权益、AI 工具、Apple 设备、建站与 SEO、文件安全和 eSIM 问题，不再发布“开发实战”分类文章。

仓库中没有 Search Console 查询、展示、点击、点击率和外链数据，因此不能仅凭文章主题断言“高点击”。后续新选题应先查看真实查询数据，再判断 UPDATE、MERGE、NEW 或 DELETE；不使用主观热度制造大量近义页面。

当前基线为 24 篇公开文章。2026-09-01 根据后台点击数据保留并重写 `book-cover` 原 URL，将微信读书未公开接口替换为有文档的 Open Library 方案；Astro 跨版本迁移、React 多文件上传和小程序账号合并仍删除，因为目前没有等价目标页或流量证据。

## 内容优先级

1. 学生权益：围绕资格、申请失败、激活、续期和毕业迁移维护现有产品页。
2. AI 与 Apple 设备：只写官方支持边界明确、设备路径可复核的登录或配置故障。
3. eSIM 与出境服务：优先购买前检查、漫游风险、号码与验证码限制。
4. 建站与 SEO：保留能帮助个人网站上线、收录和定位索引问题的任务页。
5. 文件安全：完善备份、恢复演练和教育账号到期迁移。

## 下一轮动作

### 学习资料备份更新

在 `student-file-backup-guide` 增加每月抽样恢复、毕业前 90/30/7 天检查和迁移完成判定，继续作为学校账号与文件迁移的 canonical 页面。

### 学生权益时效审计

复核 Microsoft 365、Notion、Figma、Canva、Autodesk、GitHub 和 JetBrains 的官方资格、续期、产品范围与迁移规则。只有发生实质变化时才更新正文和 `updatedDate`。

### 用真实查询决定新文章

每篇文章发布或实质更新 28 天后记录：

1. 是否正常收录，Google 选择的 canonical 是否符合预期。
2. 展示量、点击量、点击率和平均排名。
3. 实际查询是否与页面承诺一致。
4. 高展示低点击页面是否需要改标题和描述。
5. 排名接近首页的查询能否通过补充现有页面满足。
6. 只有现有页面无法承接的新意图才创建新 URL。

## 发布约束

- 新 URL 必须服务一个现有文章无法完整承接的读者状态和结果。
- 能由现有 URL 承接的意图只做 UPDATE，不创建竞争页面。
- 每篇文章只有一个分类、2–5 个实体标签，并在写作当天复核一手资料。
- 只有实质复核或重写才增加 `updatedDate`。
- 发布后检查 canonical、JSON-LD、RSS、sitemap、OG、搜索索引与移动端结果。
- 没有真实查询数据时不声称某个选题具有高搜索量或高点击率。
