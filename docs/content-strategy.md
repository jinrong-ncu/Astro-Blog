# Content Strategy

## Promise

Help a search reader finish one concrete task or understand why it cannot be completed safely. The first screen should provide the answer, constraint or next action.

Priority:

1. Troubleshooting with diagnostics, verification and rollback.
2. Tutorials with prerequisites, steps and expected outcomes.
3. Comparisons with explicit decision criteria.
4. Experience only when supported by reproducible first-hand evidence.

Do not publish isolated definitions, broad notes, fake documents, unsafe bypasses or unsupported benefit lists.

## Readers

The primary readers are students and independent developers handling software setup, education verification, Apple devices, developer tools, personal websites, file migration and selected overseas services.

## Evidence and Freshness

- Repository behavior and actual tests may be described as tested.
- Product policy uses current first-party documentation.
- Inference is labelled as inference.
- Volatile facts include a verification date and updatedDate.
- A price is never a guarantee.
- Education email is never treated as sufficient eligibility without official support.
- Referral links require immediate disclosure and a non-referral path when practical.

## Publishing Decision

Before creating a URL, search titles, descriptions, headings, tags and bodies:

- UPDATE an existing page that can own the intent.
- MERGE direct duplicates into the stronger equivalent page.
- NEW only for a materially distinct reader state and result.
- DELETE tests, unsafe instructions, fake content or pages without a useful reader task.

Published URLs remain stable unless docs/redirects.md records an equivalent permanent destination.
